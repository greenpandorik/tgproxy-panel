# Участие в разработке

[English](CONTRIBUTING.md) · **Русский**

Здесь описано, как собрать панель у себя, запустить проверки и прислать изменение. Вопросы и
идеи пишите в [Обсуждения](https://github.com/greenpandorik/tgproxy-panel/discussions), об
ошибках сообщайте в Issues. Об уязвимостях сообщайте закрыто, как описано в
[SECURITY.ru.md](SECURITY.ru.md).

## Что понадобится

- Go 1.26
- Node.js 22
- PostgreSQL 16
- Docker, только для сквозных тестов
- `make` и `openssl`

## Сборка и запуск

Создайте пользователя базы и две базы, для панели и для тестов:

```bash
createuser -s tgwp && psql -d postgres -c "ALTER USER tgwp PASSWORD 'tgwp'"
createdb -O tgwp tgwp && createdb -O tgwp tgwp_test
```

Затем соберите и запустите панель:

```bash
cp .env.example .env     # заполните MASTER_KEY и SESSION_SECRET: openssl rand -base64 32
make web                 # собирает интерфейс в web/dist
set -a; . ./.env; set +a # панель берёт настройки только из окружения
go run ./cmd/panel admin create root 'change-me-now-1'
make run                 # панель на http://localhost:8080
```

`make web` нужен до любой сборки и тестов на Go: бинарник панели встраивает `web/dist`, а в
свежем клоне репозитория этой папки нет.

При `NODE_DRIVER=gateway`, как в `.env.example`, панели нужен ещё `METRICS_TOKEN`
(`openssl rand -hex 32`). Для работы над интерфейсом можно поставить `NODE_DRIVER=mock`: тогда
панель вместо настоящих серверов использует заглушку в памяти, и `METRICS_TOKEN` можно оставить
пустым.

Для интерфейса с горячей перезагрузкой запустите `cd web && npm run dev`. Dev-сервер
перенаправляет `/api`, `/healthz` и `/metrics` на панель на `:8080`.

Другие способы запуска, через Docker или на настоящем домене, описаны в
[инструкции по установке](docs/setup.ru.md).

## Проверки

CI запускает эти команды на каждый pull request. Выполните их перед отправкой. Инструменты Go
поставьте один раз командой `make tools`: она кладёт sqlc, gofumpt, golangci-lint и плагины
protoc в `$(go env GOPATH)/bin`.

Go:

```bash
export TEST_DATABASE_URL='postgres://tgwp:tgwp@localhost:5432/tgwp_test?sslmode=disable'
go test -p 1 -race ./...
gofumpt -l ./cmd ./internal ./deploy     # если с форматированием всё в порядке, ничего не выведет
golangci-lint run ./...
```

Без `TEST_DATABASE_URL` тесты с базой молча пропускаются, поэтому задайте его. Флаг
`-p 1` обязателен: все пакеты работают с одной тестовой базой, и каждый тест очищает её таблицы.
`make test` и `make lint` делают то же короче, но `make test` запускает тесты без `-race`.

Веб-интерфейс:

```bash
cd web
npm ci
npm run typecheck
npm run lint
npm run test -- --run
npm run i18n:check
npm run build
```

## Сквозные тесты

Им нужен Docker, каждый идёт несколько минут и убирает за собой.

| Команда | Что проверяет |
|---|---|
| `make e2e` | Весь путь на движке tproxy: панель, Postgres и тестовый сервер с настоящим `tproxy-server` в контейнерах. Порт 8080 должен быть свободен. |
| `make e2e-telemt` | То же на движке telemt, с настоящим релизом telemt. Нужен доступ в интернет до дата-центров Telegram. На компьютере с ARM контейнер работает через эмуляцию и медленнее. |
| `make test-install` | `install.sh` от начала до конца в контейнере `docker:27-dind`, плюс shellcheck. |
| `make test-node-preflight` | Предварительные проверки скрипта установки сервера, без доступа к сети. |
| `make test-agent-upgrade` | `tgwp-agent upgrade` против заглушки панели, в том числе загрузку с неверной контрольной суммой. |

## Где что лежит

- SQL-запросы лежат в `internal/store/queries`. После их изменения выполните `make sqlc`: он
  пересоберёт `internal/store/db`, эти файлы руками не правят.
- Миграции лежат в `internal/store/migrations`, это файлы goose. Панель применяет их при запуске.
- Протокол агента описан в `proto/agent/v1/agent.proto`. После его изменения выполните
  `make proto`, для этого нужен `protoc`.
- Строки интерфейса лежат в `web/src/i18n/ru.json` и `en.json`. Каждую новую строку добавляйте
  в оба файла, иначе `npm run i18n:check` упадёт.
- `internal/api/rbac_walk_test.go` обходит все маршруты и проверяет, что каждый требует сессию,
  CSRF-токен и нужную роль. Намеренно открытый маршрут, изменение, разрешённое наблюдателю, или
  маршрут, который агент вызывает со своим токеном, добавьте в подходящий список:
  `publicReads`, `publicMutations`, `allowedForViewer` или `nodeTokenReads`.
- Логи пишутся через `slog`. Не пишите в логи секреты, токены и пароли.

## Как прислать изменение

1. Сделайте форк репозитория и ветку от `main`.
2. Внесите изменение и выполните проверки выше.
3. Откройте pull request в `main`. Напишите, что изменили и как проверяли. Если менялся
   интерфейс, приложите скриншот.

CI запускает три задачи: Go (сборка, форматирование, тесты с `-race` на PostgreSQL 16, линтер),
Web (типы, линтер, тесты, переводы, сборка) и сборку Docker-образа. У проекта один
сопровождающий, он читает каждый pull request. Изменение принимается, когда CI прошёл и
сопровождающий его одобрил. Сообщения коммитов пишите простыми словами: что изменилось.

Присылая изменение, вы соглашаетесь, что оно публикуется под лицензией проекта
[AGPL-3.0](LICENSE).

## Релизы

Релизы выпускает сопровождающий:

1. Укажите версию в `internal/version/version.go`.
2. Отправьте тег `vX.Y.Z`. Процесс релиза проверит, что тег совпадает с версией в исходниках,
   соберёт бинарники панели и агента для linux/amd64 и linux/arm64 с файлом `SHA256SUMS`,
   опубликует образ в `ghcr.io` и приложит бинарники к релизу на GitHub.
