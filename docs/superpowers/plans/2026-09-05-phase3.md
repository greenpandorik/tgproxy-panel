## Global Constraints

- No git; no commit steps; each task ends with the full verification set.
- Go 1.26, module `tgwebproxy`; gofumpt/golangci-lint clean incl. tests; DB tests skip without `TEST_DATABASE_URL`; `-p 1`.
- i18n ru/en parity (`npm run i18n:check`); Russian default; buttons are verbs; no marketing copy.
- Every mutation behind requireAuth + csrf + role; the router-walking RBAC test must keep passing (add new public routes to its public set explicitly and justify).
- Secrets (TOTP secrets, recovery codes, backup files) never logged; TOTP secrets encrypted with the Box; recovery codes stored hashed (argon2id is overkill; sha256 of a 10-char random code is fine because the codes are high-entropy — document).
- Public routes (`/s/{token}`, `/s/{token}.json`) are rate-limited per IP (60/min) and never reveal key labels, owner labels or notes — only hostnames, links, QR.
- Backups contain the whole DB (encrypted secrets stay encrypted because the master key is not in the DB); backup files are owner-only downloads.

### Task 27: TOTP two-factor authentication (FEATURE_TOTP)

**Files:**

- Modify: `internal/api/auth.go` (login challenge), `server.go` (routes), `web/src/pages/LoginPage.tsx`, `web/src/pages/settings/SecurityForm.tsx`, `web/src/api/auth.ts`, i18n.

**Interfaces:**
```go
package totp
func GenerateSecret() (string, error)                       // base32, 20 bytes
func ProvisioningURL(issuer, account, secret string) string  // otpauth://totp/...
func Validate(secret, code string, now time.Time) bool       // 30s step, ±1 window, SHA1, 6 digits
func NewRecoveryCodes(n int) ([]string, error)               // "xxxxx-xxxxx" lowercase base32-ish
```
API (all under FEATURE_TOTP; 404 `feature_disabled` otherwise):
- `POST /auth/totp/setup` (auth) → `{secret, otpauth_url, qr_data_uri}`; stores `totp_pending_enc`.
- `POST /auth/totp/confirm {code}` → validates against pending; moves to `totp_secret_enc`, `totp_enabled=true`, generates 8 recovery codes (returned once, stored hashed); audit `auth.totp_enabled`.
- `POST /auth/totp/disable {password, code_or_recovery}` → clears; audit.
- Login: when the user has `totp_enabled`, `POST /auth/login` does NOT issue a session; returns 200 `{totp_required:true, challenge:<signed token: userID|exp 5min>}`. `POST /auth/totp/verify {challenge, code}` (or `{challenge, recovery_code}`) issues the session, audits `auth.login` with meta `{totp:true}` or `{recovery:true}`; wrong code counts toward the account lock and IP limiter; a used recovery code is marked `used_at`.
- `GET /auth/me` includes `totp_enabled`.
Frontend: login second step (6-digit input, "use recovery code" toggle); Security tab: enable flow (QR + secret + confirm code → recovery codes shown once with copy/download), disable flow.

**Interfaces:**
```go
package backup
type Runner struct { DatabaseURL, Dir string; Exec func(ctx, name string, args ...string) ([]byte, error) } // Exec defaults to os/exec
func (r *Runner) Create(ctx, kind string) (path string, size int64, err error) // pg_dump --format=custom --no-owner → <Dir>/tgwp-<UTC ts>-<kind>.dump ; path validated inside Dir
func (r *Runner) Restore(ctx, path string) error                                // pg_restore --clean --if-exists --no-owner -d <url>
func (r *Runner) Prune(ctx, keep int, list func() ([]Entry, error), del func(id) error) (removed int, err error)
```
API (owner only): `GET /backups` → `{items:[{id,path(basename),size,kind,created_at}]}`; `POST /backups` → creates now (202 if a run is in progress → `{status:"running"}`), audit; `GET /backups/{id}/download` streams the file (`Content-Disposition`), audit `backup.download`; `DELETE /backups/{id}`. Worker `Backup`: hourly tick; when `enabled` and current UTC hour == `hour` and no backup with kind `scheduled` today → create; prune to `keep`. Tests use a fake `Exec` that writes a file.
CLI: `panel db restore <file> --yes` refuses without `--yes`, stops with an error if the panel appears to be running (lock file in DataDir written by `serve`), runs `Restore`, prints a reminder to restart.

### Task 31: Master key rotation CLI

**Files:** create `internal/store/rotate.go`, `rotate_test.go`; modify `cmd/panel/main.go` (`keys rotate`), `.env.example`, `docs/runbook.md`.

- `panel keys rotate` reads `MASTER_KEY_NEW` (base64 32 bytes) and the current `MASTER_KEY`/`MASTER_KEY_VERSION`; builds a Box with `current = version+1` and old keys; in ONE transaction re-encrypts: `profiles.secret_enc`, `access_keys.secret_enc`, `admin_users.totp_secret_enc`, `admin_users.totp_pending_enc`, `settings.telegram_alerts.bot_token_enc`; verifies every row decrypts with the new key before commit; prints the env lines to set (`MASTER_KEY=<new>`, `MASTER_KEY_VERSION=<n+1>`, `MASTER_KEY_V<n>=<old>`), never printing the keys themselves except as placeholders; refuses if the panel lock file says serve is running.
- Test: seed rows encrypted with v1, run `Rotate(ctx, st, oldBox, newBox)`, assert all blobs now report version 2 and decrypt to the same plaintext; a failure mid-way (inject a bad blob) rolls back everything.
