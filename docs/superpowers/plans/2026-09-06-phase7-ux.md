# Phase 7 — UX: form drafts, contextual help panel, node load Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal (user, 2026-09-06):** (1) every form/dialog keeps a draft after an accidental close and offers "continue draft / start new" on reopen; (2) a "?" in every dialog and page header opens a right-side help panel describing each field with examples and advice; (3) server load of nodes visible in the nodes list and as a history chart on the node page. Sidebar sections stay as they are (decided).

**Design language:** docs/superpowers/specs/2026-09-05-ui-redesign.md. i18n parity ru/en. Vitest for new hooks/components.

### Task 52: Form drafts
- `web/src/lib/drafts.ts`: `useDraft<T>(key, current: T, {ttl = 24h, initial: T})` → persists `current` (debounced 300 ms) to localStorage under `tgwp.draft.<key>` with `savedAt`; `hasDraft`, `draft`, `clear()`; expired drafts dropped on read; try/catch around storage; the draft is not written while it equals `initial`. `DraftBanner` component: "Черновик от 12:30 · [Продолжить] [Начать заново]" shown at the top of the dialog when a draft exists on open and differs from initial; "Продолжить" loads it (`form.reset(draft)`), "Начать заново" clears it. On successful submit the draft is cleared. Closing the dialog (X, Esc, backdrop, Cancel) keeps the draft.
- Apply to: keys/CreateKeyDialog (all three tabs; key = `key-create`), keys/BulkExtendDialog, nodes/CreateNodeDialog, sites/AssignTemplateDialog, the site template editor (pages/sites/* editor form: draft per template id), settings forms that have a Save button (BrandingForm per profile, Telegram/panel settings, AdminsForm create), KeyDetailDrawer edit form (per key id). Anything with react-hook-form: subscribe with `watch()`.
- Tests: hook (write/read/expire/clear/no-write-when-initial), banner behaviour in CreateKeyDialog (close → reopen → banner → continue restores label).

### Task 53: Contextual help panel (after Task 52 lands; touches the same dialog headers)
- `web/src/help/`: `HelpSheet` (right `Sheet`, width 420, scrollable) with sections: "Что это", per-field entries (name, what it does, example, tip), "Подробнее" links into docs/setup.*.md anchors on GitHub. Content in `web/src/help/content.ts` as structured objects keyed by topic id (`keys.create`, `keys.batch`, `keys.limits`, `nodes.create`, `nodes.install`, `nodes.check`, `nodes.detail`, `sites.templates`, `sites.editor`, `sites.assign`, `monitoring`, `audit`, `settings.panel`, `settings.telegram`, `settings.security`, `settings.branding`, `settings.backups`, `dashboard`) with i18n via keys `help.<topic>.<...>` in ru.json/en.json (parity enforced). Text must be concrete: the real validation rules from the code (label length, hostname rules, port range, quota units, carrier modes explained: HTTPS / WebSocket / lanes, expiry semantics, engines telemt vs tproxy, Fake-TLS domain choice), taken from the Go validators and the setup guides; no filler.
- `HelpButton topic="…"` (icon `CircleHelp`, ghost, aria-label) placed in every `DialogHeader`/drawer header and in every page header next to the title; `?` keyboard shortcut opens the help for the current page. Command palette gets "Справка по этой странице".
- Tests: HelpSheet renders a topic; every topic id used by a `HelpButton` exists in content (test walks the source with a regex or a registry); i18n parity.

### Task 54: Node load (backend + UI)
- Migration `00007_node_load.sql`: `node_stats_snapshots` + `cpu_percent real NOT NULL DEFAULT 0, mem_used_percent real NOT NULL DEFAULT 0, disk_used_percent real NOT NULL DEFAULT 0`. Stats worker writes them from the node's last health (`CpuPercent`, `MemUsedPercent`, `DiskUsedPercent`) at snapshot time; sqlc regenerate; monitoring node-series API (`GET /api/v1/monitoring/nodes/{id}/series` or wherever NodeStatsTab reads) returns `cpu_percent`, `mem_used_percent`, `disk_used_percent` per bucket (avg); tests.
- Nodes list: columns "CPU" and "RAM" as small percentage bars (from `last_health`), tone warn ≥ 80 %, danger ≥ 95 %; mobile cards show them as text. Dashboard nodes table: CPU column.
- Node page → "Статистика": chart "Нагрузка сервера" (CPU/RAM/disk lines, %) next to the sessions/traffic charts, same range selector. Overview tab keeps the current bars.
- Tests: worker test (snapshot has load), API series test, NodesPage bar rendering.
