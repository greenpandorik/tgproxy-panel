# API tokens implementation plan

Spec: ../specs/2026-10-08-api-tokens-design.md. Execute authorized implementation continuously. Separate backend, panel and static docs files allow parallel work after freezing the contract.

1. Backend: write failing PostgreSQL HTTP tests in `internal/api/api_tokens_test.go`; implement migration 27, store queries, token endpoints, Bearer middleware, explicit scope/route catalog and token audit attribution. Export `ManagementAPIRoutes() []APIRoute`, with fields Method, Path (including `/api/v1`), Scope, Summary and OwnerOnly. Scope IDs and HTTP contract are defined in the spec. Routes not in this policy remain session-only. Verify existing RBAC and CSRF tests. Run API tests against isolated database `tgwp_api_backend_test`.
2. Panel: use the spec's exact endpoints and JSON fields in `web/src/api/apiTokens.ts`; add the settings section, RU/EN strings and accessible dialogs. Tests must show secret only once and never retain it after close; test read-only/viewer presets, validation and revocation. Use existing UI components. Run frontend suite, typecheck, lint and build.
3. Docs: create localized API pages using current site's guide styles and metadata; integrate home links, sitemap and llms.txt. Mark route catalog with an HTML comment insertion region so the build can generate it from the backend contract. Write real curl/Python examples. Do not require external API calls for reading docs.
4. Contract integration: build a Go command to export OpenAPI from `ManagementAPIRoutes`; supply precise request/response schemas for the common node/user operations and parameters for their lists. Add reproducibility and route existence checks. Copy contract to the site and render catalog in both languages. Validate generated spec and site.
5. Full verification/review: one isolated database for serialized full Go race tests; full web checks; real browser mobile/desktop create/list/revoke and site docs checks with an isolated local panel. Independent whole-feature security review. Fix material findings, rerun affected checks, then create reviewable commits/draft PR; report live publication status explicitly.

Review focus: (1) malformed Bearer plus valid cookie cannot authenticate, (2) GET routes carrying secrets are not read-only, (3) token privilege changes when account role changes, (4) bearer cannot mint more credentials, (5) one-time secret survives list refresh but disappears permanently after close. Tests belong to tasks 1 and 2 respectively.
